NanoBO v0.2：功能与数据格式

本版把实验空间、推荐结果和模型检查放在同一个本地桌面流程中：定义变量 → 导入实测结果 → 生成合法配方 → 做实验并回填 → 查看预测与验证。教学示例全部使用模拟数据。

本版可以做什么

功能 操作与含义
原单位步长 在变量表设置步长，例如体积每次增加 0.1 mL。档位从变量下限开始，推荐前生成合法档位，推荐后不再四舍五入或强制归一化。上限不在档位上时不会硬加上限。
总量与线性约束 “配方约束 / 候选表”中填写系数和等号／不等号，例如 A + B + C = 2.5。不同单位不会自动换算，需先统一单位或在系数中换算。
配比约束 例如 0.5 ≤ A/B ≤ 2。分母必须大于零；最小和最大配比相同时支持固定配比。
合法候选表 导入预先列好的可执行配方，下一批仅从表中选择。表中只放变量列，不能放尚未测量的目标值。
Excel / CSV 导入 支持 .xls、.xlsx、UTF-8 .csv；多工作表时选择要读的一张。结果表的列名必须恰好对应全部变量和全部目标。
单目标数值优化 BoTorch 工作流显示候选的预测均值、预测标准差和采集分值；没有足够数据时先做分散初始设计。
Pareto 多目标 每个目标单独指定最大化或最小化，查看实测 Pareto 前沿、二维／三维目标折衷和超体积历史。Pareto 点表示当前实测结果中的非支配点。
分类主动学习 为“成功／失败”或形貌类别等文字标签选下一批实验。预先设置至少两个标签；观察到两个类别后，按分类熵优先探索模型较不确定的候选。
验证与导图 “分析与交叉验证”使用与本工作流推荐相同的固定模型重新拟合，给出留出预测、误差及指标。可导出当前图为 PNG／PDF／SVG、候选预测为 CSV。

图表包括候选预测与区间、均值与不确定性、采集分值排序、预测—实测、验证误差、观测分布、实测历史、Pareto、超体积历史，以及分类概率、分类熵、类别计数和混淆矩阵。图形面板支持缩放、平移和候选点查看。

引擎范围与结果解释

新增的步长、候选表、联合约束、Pareto 和分类任务使用界面的 BoTorch 工作流。Gryffin 和 Atlas 保留原生推荐；Gryffin 的多目标优先级仍走 Chimera。选择不兼容的经典引擎会给出明确提示，不会静默换算法。

数值单目标使用 BoTorch SingleTaskGP，多目标使用 ModelListGP；采集函数分别为 qLogEI 和 qLogNEHVI。分类使用固定的高斯过程分类器和熵排序。界面没有新增 GP／随机森林／SVM 或 EI／UCB 的算法菜单。不同任务和数据需要验证，不能由这些模型名称推断本软件在所有体系中都更好。

预测标准差表示模型给出的不确定性，预测区间不等于实验一定落入的范围。采集分值用于比较本次候选中的实验价值，不等同于性能预测。分类概率也不等同于产率等化学性能；尚未出现的类别不补零，其概率不会被伪装成已知结果。

明确的计算边界

  • 有限档位组合最多遍历 200000 组源组合，再筛选约束和已测／待实验。超过此范围时需增大步长、缩小范围或导入预先筛选的候选表；不会静默截断网格。
  • 一次模型排序最多使用 4096 个合法未做条件。若有限域更多，按固定随机种子取子集；连续域使用固定种子的有界可行采样。候选排序代表本次候选池，不构成整个连续实验空间的全局最优保证。
  • 连续线性等式先解连续变量，再检查边界与其他规则；与步长一起使用时保留原始档位。未找到可行样本会报告错误并提示检查规则或导入合法候选表。
  • 已测和已排队条件不会再次推荐。连续变量在参数跨度的 1e-6 内按近重复处理；候选表中此类条件会明确拒绝导入。实测重复实验允许保留。
  • 历史实测条件可以不在当前候选表内，但仍需符合项目的变量边界、步长及约束。待实验条件必须来自当前候选表。
  • 留一验证至少需要 3 条实测记录。超过 30 条时，均匀选择最多 30 条分别留出，每折仍用其他全部记录训练，并报告实际验证数量。分类留一后若训练集只剩一个类别，该折跳过。
  • 数值验证报告 RMSE、MAE、R²；实测值完全相同时 R² 留空。分类验证报告准确率和混淆矩阵。它们用于检查当前数据，不是独立外部实验验证。
  • 导入时不把缺失值填成 0；重复表头、缺失单元格、非法档位和未知分类标签会报错。全空白行跳过。Excel 公式读取已有缓存结果；无缓存的公式单元格按缺失处理，不在应用中执行公式。

项目 JSON 格式示例

已有项目可继续打开；新增字段省略时默认 task: "optimization"、objective_mode: "hierarchical"、无约束及无候选表。项目备注、历史、单位和额外顶层元数据会保留。

{
  "name": "总量固定的配方优化",
  "engine": "bo-mcp",
  "task": "optimization",
  "objective_mode": "hierarchical",
  "seed": 42,
  "batch_size": 2,
  "parameters": [
    {"name": "A", "type": "continuous", "low": 0, "high": 1, "step": 0.1, "unit": "mL"},
    {"name": "B", "type": "continuous", "low": 0, "high": 1, "step": 0.1, "unit": "mL"}
  ],
  "objectives": [{"name": "yield", "goal": "max", "tolerance": 0.2}],
  "constraints": [
    {"kind": "linear", "coefficients": {"A": 1, "B": 1}, "relation": "eq", "rhs": 1, "tolerance": 1e-8},
    {"kind": "ratio", "numerator": "A", "denominator": "B", "low": 0.2, "high": 5}
  ],
  "candidates": [],
  "observations": [{"A": 0.3, "B": 0.7, "yield": 0.8}],
  "pending": [],
  "notes": "模拟格式示例，不是实验建议。"
}

candidates: [] 表示由范围、步长和约束构建候选域；也可以改为参数字典列表，如 [{"A": 0.4, "B": 0.6}, {"A": 0.6, "B": 0.4}]。分类任务改为 task: "classification" 并增加 classification: {"labels": ["成功", "失败"]}；目标只保留一个标签列，实测值填写相应文字标签。Pareto 则设为 objective_mode: "pareto"，并提供至少两个有各自 goal 的数值目标。
